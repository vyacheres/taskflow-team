TaskFlow Team — ER-модель
====================================
Нотация Мартина (IE). Сущность — прямоугольник в два яруса: сверху строка
с именем, ниже список атрибутов (шапка и поля под ней). Связь «назначение»
показана отдельно: над блоками — подпись и кратность, на линии между
шапками — тот же фрагмент ○< … || (мост между разделителями ├─…─┤).

  ┌──────────────────────────────────────────────────────────────────────────────────────┐
  │                                                                                      │
  │                         ○<────────── назначение ──────────||                         │
  │                             (1 : N) · исполнитель задачи                             │
  │                                                                                      │
  │    ┌─────────────────────────┐                          ┌─────────────────────────┐  │
  │    │       employees         │                          │          tasks          │  │
  │    ├─────────────────────────┤    ○<──────────────||    ├─────────────────────────┤  │
  │    │ id                      │                          │ id                      │  │
  │    │ full_name               │                          │ title                   │  │
  │    │ position                │                          │ description             │  │
  │    │ email                   │                          │ deadline                │  │
  │    │ team                    │                          │ priority                │  │
  │    └─────────────────────────┘                          │ status                  │  │
  │                                                         │ employee_id             │  │
  │                                                         │ created_at              │  │
  │                                                         └─────────────────────────┘  │
  │                                                                                      │
  └──────────────────────────────────────────────────────────────────────────────────────┘

  Со стороны employees: ○< — ноль или много задач.
  Со стороны tasks:     || — ровно один сотрудник.

  Связь по смыслу: 1 : N.


Описание схемы
--------------

Имя сущности вынесено отдельной строкой над таблицей атрибутов — так проще
читать модель и переносить её в SQL: каждый блок соответствует таблице
employees или tasks.

employees описывает сотрудника: id, full_name, position, email, team.

tasks описывает задачу спринта: id, title, description, deadline, priority,
status, employee_id (ссылка на employees), created_at.

Связь «назначение» показана дважды для наглядности: вынесена над сущностями
(подпись и те же ○< … ||) и продублирована на линии между разделителями
под шапками таблиц — как «мост» между employees и tasks. У сотрудника
○<: задач может не быть или несколько. У задачи ||: ровно один
исполнитель. Итог — один ко многим от employees к tasks.
